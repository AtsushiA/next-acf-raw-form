# NExT ACF Raw Form Output Block

ACFフィールドの内容をエスケープせずにそのまま出力するWordPressブロックプラグインです。MarketoやPardotなどのフォームコードの埋め込みに最適です。

- **バージョン:** 0.4.0
- **動作確認済みWordPress:** 6.8
- **必要WordPress:** 6.1以上
- **必要PHP:** 7.4以上
- **ライセンス:** GPLv2 or later
- **作者:** NExT-Season with WordPress Telex

---

## 概要

Advanced Custom Fields（ACF）のテキストフィールドに保存されたコンテンツを、HTMLエスケープや余分なスタイルを一切加えずにそのまま出力するブロックです。

フォームコード（`<script>` タグ）やiframe、その他のHTMLスニペットをACFフィールドに保存してページに埋め込みたい場合に特に有効です。

## 機能

- ACFフィールドのHTMLコンテンツをエスケープせずに出力
- ブロックインスペクターからACFフィールド名を設定可能
- 任意のACFテキストフィールドに対応
- フォーム・iframe・HTMLスニペットの埋め込みに最適
- ダイナミックレンダリングにより常に最新のコンテンツを表示
- **ポストコンテンツ内**での `wpautop` による `<script>` タグへの `<p>` 挿入を防止
- **ブロックテンプレート内**（サイドバー等）でも正しくレンダリング
- 旧ブロック名 `telex/block-telex-acf-raw-form` との後方互換性を維持

## 必要要件

- [Advanced Custom Fields（ACF）](https://www.advancedcustomfields.com/)プラグインがインストール・有効化されていること
- ACFフィールドが現在の投稿コンテキストで利用可能であること

## インストール

1. プラグインファイルを `/wp-content/plugins/next-acf-raw-form` ディレクトリにアップロードするか、WordPressの管理画面からプラグインをインストールします。
2. 管理画面の「プラグイン」からプラグインを有効化します。
3. Advanced Custom Fieldsプラグインがインストール・有効化されていることを確認します。
4. 投稿またはページにブロックを追加し、ブロック設定でACFフィールド名を入力します。

## 使い方

1. ACFで任意のテキストフィールドを作成します（例：`application_form`）
2. 投稿またはページに「ACF Raw Form Output」ブロックを追加します
3. ブロック設定（インスペクター）で **ACF フィールド名**（APIネーム）を入力します
4. 指定したフィールドのコンテンツがそのまま表示されます

> **注意:** ブロック設定に入力するのはACFの「フィールド名」（管理画面でラベル下に表示されるAPIネーム）です。ラベル名ではありません。

### ブロックの配置場所

| 配置場所 | 動作 |
|---------|------|
| 投稿・ページのコンテンツ内 | wpautop による `<script>` タグへの `<p>` 挿入を防止して出力 |
| ブロックテンプレート内（サイドバー等） | wpautop は適用されないため、そのまま出力 |

## よくある質問

**ACFプラグインは必須ですか？**
はい。このブロックはAdvanced Custom Fieldsプラグインが必要です。

**どのタイプのACFフィールドに対応していますか？**
テキストフィールドおよびテキストエリアフィールドに対応しています。エスケープやフォーマットを行わず、そのままの内容を出力します。

**生のHTMLを出力しても安全ですか？**
このブロックは意図的にエスケープを行わないため、信頼できるコンテンツのみに使用してください。ACFフィールドに保存するコンテンツは管理者が管理していることを確認してください。

**WYSIWYGフィールドに対応していますか？**
TinyMCEが `<script>` タグを `<p>` で囲む場合がありますが、このプラグインの `render.php` で自動的に除去します。

**リピーターフィールドなど複雑なフィールドタイプには対応していますか？**
このブロックはシンプルなテキストフィールド向けに設計されています。複雑なフィールドタイプにはカスタム開発が必要になる場合があります。

## 開発

### ディレクトリ構成

```
next-acf-raw-form/
├── src/               # ソースファイル（JS・SCSS・PHP）
│   ├── block.json
│   ├── index.js
│   ├── edit.js
│   ├── save.js
│   ├── view.js
│   ├── render.php
│   ├── style.scss
│   └── editor.scss
├── build/             # ビルド成果物（@wordpress/scripts で生成・gitignore）
├── next-acf-raw-form.php
├── package.json
└── readme.txt
```

### ビルド

```bash
npm install
npm run build
```

開発時のウォッチモード:

```bash
npm run start
```

### プラグインZIPのパッケージング

```bash
npm run plugin-zip
```

- 旧ブロック名 `telex/block-telex-acf-raw-form` の後方互換性を維持
